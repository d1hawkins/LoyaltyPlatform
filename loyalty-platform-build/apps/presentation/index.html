Daiso's data is physically separated — no cross-tenant access is possible. Each tenant has its own database, encryption keys, and Key Vault secret resolution.

POS Integration

POS Integration — 3 API Calls

1. Member Lookup
GET /v1/members?phone=7012060906 → { name, tier, points, offers }
2. Record Transaction
POST /v1/transactions { memberId, amount, skuList, storeId, associateId } → { pointsEarned, newBalance }
3. Redeem Offer
POST /v1/redemptions { memberId, offerId, channel } → { discountValue, couponCode }
Your POS sends these 3 calls at checkout. Everything else happens automatically — tier evaluation, notifications, analytics, fraud checks.

Earn Model

Visit-Based Earn Model

Perfect for Daiso

Daiso's high-frequency, low-ticket shopping pattern means per-visit earning is more rewarding and engaging than per-dollar.

V

Per-Visit Earn Mode

Flat points awarded per qualifying transaction, not per dollar

$

Minimum Spend Threshold

Configurable minimum (e.g., $5.00) to qualify a visit

D

Daily Visit Cap

Max visits per day prevents gaming (e.g., 2 per day)

M

Visit Milestone Rewards

Automatic SMS coupons at visit thresholds

Example Configuration

earnMode: per-visit
pointsPerVisit: 10
minSpend: $5.00
maxVisitsPerDay: 2

Visit Milestone SMS:

"Congrats! You've visited Daiso 5 times this month. Here's a $5 reward! Show code: DAISO5OFF"

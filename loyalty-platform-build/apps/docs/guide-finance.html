1. Points Liability (ASC 606 / IFRS 15)

What Is Points Liability?

Under ASC 606 (US GAAP) and IFRS 15 (international), loyalty points represent a performance obligation. When a customer earns points, a portion of the transaction revenue must be deferred until those points are redeemed or expire. This deferred amount is the points liability.

Net Liability = Outstanding Points × Point Value × (1 − Breakage Rate)

Where to Find It

Navigate to Admin Portal → Reports → Finance tab → Points Liability card.

Fields Explained

FieldDescriptionExample
Outstanding Points Total unexpired, unredeemed points across all active members 2,450,000 points
Point Value The monetary value of one point (based on your earn rate and redemption value) $0.01 per point
Gross Liability Outstanding Points × Point Value — the maximum possible cost $24,500.00
Breakage Estimate Percentage of points expected to expire without redemption 25% ($6,125.00)
Net Liability Gross Liability − Breakage — the amount to carry on the balance sheet $18,375.00

Breakage Rate

Breakage is the percentage of points that are expected to go unredeemed (they expire or the member becomes inactive). The platform defaults to a 25% breakage rate.

IndustryTypical Breakage
Retail / General Merchandise20–30%
Grocery15–20%
Airlines / Hotels10–15%
Credit Card Rewards25–35%

To adjust the breakage rate, navigate to Program Config → Finance Settings and update the breakage percentage. Consult your auditor before changing this value, as it directly impacts your reported liability.

When to Report

  • Monthly: Pull the liability report for internal management reporting and budget tracking
  • Quarterly: Include net liability in your quarterly financial statements
  • Annually: Full reconciliation with your external auditors, including breakage rate validation

2. Points Flow Report

The Points Flow report shows the movement of points through the system over a selected period.

MetricDescription
Points IssuedTotal points earned from transactions and manual adjustments
Points RedeemedTotal points used for rewards and offers
Points ExpiredTotal points that reached their expiry date without redemption
Points VoidedPoints reversed due to transaction voids or corrections
Net ChangeIssued − Redeemed − Expired − Voided = change in outstanding balance

Using for Reconciliation

To reconcile the points balance at month-end:

  1. Take the opening balance (outstanding points at start of month)
  2. Add points issued during the month
  3. Subtract points redeemed, expired, and voided
  4. The result should equal the closing balance shown in the Points Liability report
Closing Balance = Opening Balance + Issued − Redeemed − Expired − Voided
Reconciliation Discrepancy
If the calculated closing balance does not match the reported balance, check the Audit Log for manual adjustments made during the period. Manual adjustments (goodwill credits, corrections) appear in the "Issued" column but are tagged separately in the detailed export.

3. Redemption Reserve

Monthly Cash Flow Impact

The Redemption Reserve report estimates the monthly cash outflow from points redemptions:

  • This Month's Redemptions: Total monetary value of points redeemed
  • Rolling 3-Month Average: Average monthly redemption value over the past 3 months
  • Projected Next Month: Estimated redemption based on historical trends and upcoming expiries

Cost Per Point Redeemed

This metric shows the actual cost to the business for each point that is redeemed. It accounts for the fact that not all points are equal — some are redeemed for percentage discounts, others for fixed amounts.

Cost Per Point = Total Discount Value Given / Total Points Redeemed

Budget Forecasting

Use the Redemption Reserve data to forecast loyalty program costs:

  1. Review the rolling 3-month average redemption value
  2. Factor in planned promotions (double points events increase future redemptions)
  3. Account for seasonality (holiday shopping increases both earning and redemption)
  4. Apply the breakage rate to estimate what percentage of newly issued points will never be redeemed

5. Data Export

Exporting Reports to CSV

Every report in the Admin Portal includes an Export button that downloads the data as a CSV file. Exported files include:

  • All visible columns with headers
  • The selected date range filter
  • A timestamp row showing when the export was generated

Connecting to Power BI / Excel

For recurring reports, connect Power BI or Excel directly to the loyalty API:

  1. Generate a Read Only API key in the Admin Portal (see API Keys)
  2. In Power BI, use the Web data source connector
  3. Enter the API endpoint URL with your date range parameters
  4. Add the Ocp-Apim-Subscription-Key header with your API key
  5. Set up a refresh schedule (daily or weekly)

API Endpoints for Automated Reporting

Key API endpoints for financial reporting:

GET /v1/admin/reports/liabilityCurrent points liability snapshot
GET /v1/admin/reports/points-flowPoints issued/redeemed/expired by period
GET /v1/admin/reports/redemption-reserveMonthly redemption cost and projections

6. Compliance

GDPR Data Handling

The loyalty platform handles personally identifiable information (PII) with the following safeguards:

  • Encryption at Rest: All PII fields (name, email, phone) are encrypted using AES-256 in the database
  • Encryption in Transit: All API communication uses TLS 1.2+
  • Data Deletion: Members can request deletion through the Member Portal. Admins can process deletion requests via the Admin Portal. PII is anonymized while financial records (anonymized transaction data) are retained for accounting purposes.
  • Data Export: Members can request a full export of their data in machine-readable format (JSON)
  • Consent Management: Enrollment captures explicit opt-in consent. Communication preferences are member-controlled.

Audit Trail

Every administrative action is logged with:

FieldDescription
ActorThe admin user who performed the action (email and user ID)
TimestampExact date and time (UTC) of the action
EntityWhat was changed (member, tier, offer, config)
ActionWhat was done (create, update, delete, adjust)
Before StateThe entity's state before the change
After StateThe entity's state after the change

The audit log is immutable — entries cannot be edited or deleted. Export the log for compliance reviews using the Export button on the Audit Log page.

Data Retention Policies

  • Active Member Data: Retained for the lifetime of the member account
  • Transaction Records: Retained for 7 years (financial compliance requirement)
  • Audit Logs: Retained for 7 years
  • Deleted Member Data: PII is anonymized immediately upon deletion. Anonymized records follow standard retention periods.
  • API Logs: Retained for 90 days

7. Per-Visit Liability

How Liability Differs in Per-Visit Mode

In per-dollar mode, liability varies with transaction amounts — a $50 purchase creates more liability than a $5 purchase. In per-visit mode, every qualifying visit creates the same liability regardless of the transaction total (the flat points-per-visit amount).

Per-Visit Liability = Qualifying Visits × Points Per Visit × Point Value × (1 − Breakage Rate)

Advantages for Financial Forecasting

  • Predictability: Each qualifying visit generates exactly the same liability. No need to estimate average transaction values.
  • Simple budgeting: If you expect 10,000 qualifying visits per month and award 10 points per visit at $0.01/point, your gross monthly liability is exactly $1,000.
  • Decoupled from revenue: Liability is driven by visit count, not revenue. Revenue can grow without proportionally increasing liability.

Monitoring Visit Qualification Rate

Not all transactions qualify as visits (those below the minimum spend threshold do not earn points). The visit conversion rate in the Operations report shows what percentage of total transactions qualify. If the rate drops, it may indicate that the threshold needs adjustment.

8. Visit Conversion Metrics

Navigate to Reports → Operations to find visit conversion metrics. These are particularly important for finance:

MetricFinance Relevance
Visit Conversion Rate What % of transactions create points liability? A higher rate means more liability per transaction but also higher member engagement.
Qualified Visits (Daily / Monthly) Direct input to liability forecasting. Multiply by points-per-visit and point value for gross liability.
Non-Qualifying Transactions Transactions below the minimum spend threshold. These create no points liability.

Adjusting the Threshold

If the visit conversion rate is too high (above 95%), the minimum spend threshold may be too low and creating unnecessary liability on trivial transactions. If it's too low (below 60%), members may feel the program is unrewarding. The recommended target is 70–85%. Any threshold change should be coordinated with marketing and approved by finance, as it directly impacts future liability.

9. Transaction Traceability

Every transaction now includes enrichment fields that enable full traceability for reconciliation and audit:

FieldReconciliation Use
storeId / storeNameMatch transactions to store-level P&L reports
registerIdIdentify which terminal processed the transaction
associateId / associateNameAudit trail for who processed the transaction
sourceChannelSegment liability by channel (in-store vs online vs self-checkout)
sourceSystemIdentify which POS system submitted the transaction (Square, Shopify, kiosk, etc.)
orderRefCross-reference with the POS system's order records for reconciliation
metadataCustom tags for campaign tracking, promotional attribution, etc.

Using Order References for Reconciliation

The orderRef field allows you to match loyalty transactions against your POS system's order records. When investigating a discrepancy:

  1. Export the Points Flow report for the period in question
  2. Use the orderRef column to cross-reference each transaction against the POS settlement report
  3. Filter by storeId to isolate store-level discrepancies
  4. Use sourceSystem to identify which POS integration may have issues

10. Report Walkthrough

Finance Tab Overview

When you open Reports → Finance, you'll see four report cards:

  1. Points Liability: The top-level card showing outstanding points, gross liability, breakage estimate, and net liability. This is your ASC 606 number. Use the date selector to view liability as of a specific date for period-end reporting.
  2. Points Flow: A table showing points issued, redeemed, expired, and voided for the selected period. Use "Group By" to switch between daily, weekly, and monthly views. The net change row reconciles opening and closing balances.
  3. Redemption Reserve: Shows this month's redemption cost, the rolling 3-month average, and the projected next month. Use this for cash flow forecasting.
  4. Revenue Attribution: Compares member vs non-member revenue, average basket sizes by tier, and the spend lift percentage. This is your core ROI metric.

Exporting for Period-End Close

  1. Set the date range to the period being closed (e.g., Q1 2026)
  2. Click Export on each card to download CSV files
  3. Verify the Points Flow reconciliation: Opening + Issued - Redeemed - Expired - Voided = Closing
  4. Attach the Points Liability and Points Flow CSVs to your period-end working papers
  5. If using per-visit mode, also export the Operations → Qualified Visits report to document the volume driver for liability

11. Common Finance Tasks

"Prepare the quarterly liability report"

  1. Navigate to Reports → Finance → Points Liability
  2. Verify the outstanding points total matches your general ledger opening balance + net flow
  3. Review the breakage rate — is 25% still appropriate based on actual redemption trends?
  4. Compare the Points Flow Report for the quarter: issued, redeemed, expired, voided
  5. Export both reports to CSV
  6. Calculate: Opening Liability + (Points Issued × Point Value) − (Points Redeemed × Point Value) − (Points Expired × Point Value) = Closing Liability
  7. The closing liability should match the Points Liability card. Document any variance notes for your auditor.

"Investigate a disputed transaction"

  1. Get the transaction ID, member phone number, or order reference from the customer
  2. Navigate to Transactions in the Admin Portal and search by the identifier
  3. Open the transaction detail to see: store, date/time, associate, items, points earned, and any applied offers
  4. Check the Points Ledger on the member's profile to see the exact credit entry
  5. Check the Audit Log for any manual adjustments related to this transaction
  6. If the transaction was voided, the void entry appears in both the transaction list and the ledger

"Calculate program ROI for a board presentation"

Pull these reports to build a comprehensive ROI analysis:

  1. Revenue Attribution: Member revenue vs non-member revenue, and spend lift percentage
  2. Points Liability: Net liability as the "cost" of the program
  3. Redemption Reserve: Monthly cash outflow from redemptions
  4. Tier Distribution: Show member progression as evidence of engagement
  5. Cohort Retention (from Marketing reports): Show that loyalty members return more often

The ROI formula:

ROI = (Incremental Member Revenue − Program Cost) / Program Cost × 100%

Where:

  • Incremental Member Revenue = (Member Avg Basket − Non-Member Avg Basket) × Number of Member Transactions
  • Program Cost = Net Liability Change + Redemption Cost + Platform Fees + Marketing Spend on Loyalty Campaigns

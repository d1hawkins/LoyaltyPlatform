API Reference

Complete endpoint documentation for all Loyalty Platform services.

Interactive API Explorer
Try endpoints live with Swagger UI. Base URL: https://loyalty-dev-apim-5rdrqh.azure-api.net

Member Service

Enrollment, profile management, lookup, and GDPR operations. All endpoints under /member/v1/members.

POST /member/v1/members

Enroll a new loyalty member.

{
  "phone": "+15555551234",
  "firstName": "Jane",
  "lastName": "Doe",
  "email": "jane@example.com",
  "dateOfBirth": "1990-05-15",
  "enrolledChannel": "pos | ecommerce | mobile | admin"
}

Returns 201 with full MemberDTO. Returns 409 DUPLICATE_MEMBER if phone or email already enrolled.

GET /member/v1/members/:id

Get a member by ID. Returns full MemberDTO with decrypted PII.

GET /member/v1/members?phone={phone}

POS hot-path lookup by phone number. Returns MemberSummaryDTO. Target: p99 < 100ms at 500 RPS.

GET /member/v1/members?email={email}

Lookup by email. Returns MemberSummaryDTO.

PATCH /member/v1/members/:id

Update member profile fields: firstName, lastName, email, phone, communicationPrefs. Updating email or phone triggers re-encryption and duplicate check.

POST /member/v1/members/:id/status

Transition member status.

{
  "status": "active | suspended | closed",
  "reason": "explanation"
}

Valid transitions: active → suspended/closed, suspended → active/closed. Closed is terminal.

DELETE /member/v1/members/:id

GDPR soft delete. Sets is_deleted=1, invalidates caches, publishes member.deleted. Returns 204.

GET /member/v1/members/:id/export

GDPR data export as JSON. Returns profile, ledger summary, and transaction reference.

GET /member/v1/members/:id/ledger?after=&limit=

Paginated points ledger. Default limit 50, max 200. Cursor-based pagination via after parameter.

{
  "items": [
    {
      "id": "ledger-uuid",
      "memberId": "member-uuid",
      "transactionId": "txn-uuid",
      "delta": 25,
      "balanceAfter": 125,
      "reason": "earn",
      "createdAt": "2026-04-10T12:00:00Z"
    }
  ],
  "nextCursor": "base64-encoded-cursor"
}

Loyalty Engine

Transaction processing, points calculation, and the immutable ledger. All write endpoints require Idempotency-Key.

POST /engine/v1/transactions

Record an earn transaction. Amounts in minor currency units (cents). Includes transaction enrichment fields for full traceability.

{
  "memberId": "uuid",
  "channel": "pos | ecommerce | mobile | admin",
  "amount": 2500,
  "currency": "USD",
  "skuList": [
    { "sku": "COFFEE-12", "categoryId": "beverages", "amount": 2500 }
  ],
  "locationId": "store-42",
  "occurredAt": "2026-04-10T10:00:00Z",
  "storeId": "DAISO-042",
  "storeName": "Daiso Carrollton",
  "registerId": "REG-01",
  "associateId": "EMP-1001",
  "associateName": "Jane Smith",
  "sourceChannel": "in-store | online | self-checkout",
  "sourceSystem": "square | shopify | kiosk | custom",
  "orderRef": "ORD-2026-04-10-1234",
  "metadata": { "campaign": "spring-sale" }
}

Enrichment fields: storeId, storeName, registerId, associateId, associateName, sourceChannel, sourceSystem, orderRef, and metadata are all optional but recommended for full traceability. They are stored with the transaction and available in reports, exports, and the admin transaction detail view.

Response 201 (per-dollar mode):

{
  "transactionId": "uuid",
  "pointsEarned": 25,
  "newBalance": 125,
  "tierId": "silver",
  "earnMode": "per-dollar",
  "appliedMultipliers": [
    { "source": "category:beverages", "multiplier": 2, "points": 25 }
  ]
}

Response 201 (per-visit mode):

{
  "transactionId": "uuid",
  "pointsEarned": 10,
  "newBalance": 135,
  "tierId": "silver",
  "earnMode": "per-visit",
  "qualifiedVisit": true,
  "visitCountToday": 1,
  "appliedMultipliers": [
    { "source": "tier:silver", "multiplier": 1.25, "points": 12 }
  ]
}

When earnMode is "per-visit", the response includes qualifiedVisit (whether this transaction met the minimum spend threshold) and visitCountToday (how many qualifying visits this member has made today). If the member has exceeded maxVisitsPerDay, qualifiedVisit will be false and pointsEarned will be 0.

POST /engine/v1/transactions/:id/void

Reverse a transaction within the void window (default 168h).

{ "reason": "customer return" }

Response includes pointsReversed, newBalance, and negativeBalanceFlag.

GET /engine/v1/members/:id/balance

Get current points balance. Served from Redis cache (300s TTL).

{
  "balance": 125,
  "lastUpdated": "2026-04-10T10:00:00Z"
}

POST /engine/v1/members/:id/adjustments

Manual points adjustment (admin only). Positive or negative delta.

{
  "delta": 500,
  "reasonCode": "adjust | bonus",
  "notes": "goodwill credit"
}

POST /engine/v1/redemptions

Burn points for an offer redemption.

{
  "memberId": "uuid",
  "offerId": "offer-1",
  "pointsToBurn": 200,
  "redemptionContext": {}
}

Offer Service

Offer catalog, eligibility engine, and code management.

GET /v1/offers

List all offers. Filter with ?type=percent|fixed|bogo|threshold|visit-based|free-item and ?active=true|false.

POST /v1/offers

Create an offer (admin/manager). Supports targeting rules via targetingJson.

Visit-based offer fields:

{
  "type": "visit-based",
  "name": "5 Visits = $5 Off",
  "reward": { "type": "fixed", "amount": 500 },
  "visitRules": {
    "visitsRequired": 5,
    "minSpendPerVisit": 500,
    "minItemsPerVisit": 1,
    "qualifyingChannels": ["in-store", "self-checkout"],
    "qualifyingStores": ["all"],
    "countingMode": "per-transaction | per-day"
  },
  "eligibility": {
    "tiers": ["all"],
    "startDate": "2026-05-01",
    "endDate": "2026-06-30"
  }
}

Free item offer fields:

{
  "type": "free-item",
  "name": "Free Storage Bin",
  "reward": {
    "type": "free-item",
    "sku": "STORAGE-BIN-M",
    "maxValue": 500
  },
  "visitRules": {
    "visitsRequired": 5,
    "minSpendPerVisit": 500
  }
}

Both sku and maxValue are optional. If sku is omitted, the member can choose any item. If maxValue is omitted, any item value is accepted.

GET /v1/members/:memberId/offers

Get personalized eligible offers for a member. Sorted by redeemability, then expiry.

POST /v1/redemptions

Redeem an offer. Validates eligibility, deducts points if applicable, increments redemption counters.

{
  "memberId": "uuid",
  "offerId": "uuid",
  "channel": "pos",
  "redemptionCode": "DAISO-XXXX-YYYYYY"  // optional — required for code-bound visit offers
}

Code-Bound Validation: For visit-based offers that issued a coupon code, the redemptionCode field is required. The system validates:

  • The code exists and matches the offer
  • The code is assigned to the requesting member (member binding)
  • The code has not already been used (single-use enforcement)

Error Responses:

  • 422 INVALID_CODE — Code does not exist
  • 422 CODE_OFFER_MISMATCH — Code belongs to a different offer
  • 403 CODE_MEMBER_MISMATCH — Code is bound to a different member
  • 409 CODE_ALREADY_USED — Code has already been redeemed
  • 422 CODE_EXPIRED — Code has expired
  • 422 CODE_REQUIRED — Visit-based offer requires a coupon code

POST /v1/offers/:id/generate-codes

Bulk-generate unique redemption codes (admin/manager).

{
  "count": 100,
  "prefix": "SUMMER"
}

Analytics Service — Reporting Endpoints

Eight new reporting endpoints under /v1/analytics/reports for finance and marketing analytics.

Finance Reports

GET /v1/analytics/reports/liability

Points liability report for balance sheet recognition (ASC 606 / IFRS 15). Returns gross liability, breakage estimate, net liability, breakage rate, and cost per point.

GET /v1/analytics/reports/points-flow?from=&to=&groupBy=day

Points issuance and redemption flow. Daily/weekly/monthly breakdown of points issued, redeemed, expired, voided, and net change.

GET /v1/analytics/reports/redemption-reserve

Redemption reserve (monthly). Breakdown of redemptions with count, points used, discount value, and cost per point.

GET /v1/analytics/reports/revenue-attribution?from=&to=

Revenue attribution. Daily transaction volume, spend, avg basket, and spend per member for loyalty ROI analysis.

Marketing Reports

GET /v1/analytics/reports/engagement-funnel

Member engagement funnel. Conversion rates from enrollment through first purchase, repeat, frequent, tier upgrade, and redemption.

GET /v1/analytics/reports/at-risk-members?daysInactive=60&minBalance=1&limit=50

At-risk members. Members with positive balance who haven't transacted in a configurable window. Used for win-back campaigns.

GET /v1/analytics/reports/tier-distribution

Tier distribution. Member count and percentage at each tier level.

GET /v1/analytics/reports/offer-performance?from=&to=

Offer performance. Per-offer metrics including redemption count, rate, and revenue impact.

Operations Reports

GET /v1/analytics/reports/visit-analytics?from=&to=&groupBy=day

Visit analytics for per-visit earn mode. Returns qualified visits, total transactions, visit conversion rate, and daily/weekly/monthly trends.

{
  "qualifiedVisits": 8420,
  "totalTransactions": 11200,
  "conversionRate": 0.7518,
  "avgPointsPerVisit": 10,
  "dailyTrend": [
    { "date": "2026-04-20", "qualifiedVisits": 312, "totalTransactions": 415, "rate": 0.752 },
    { "date": "2026-04-21", "qualifiedVisits": 298, "totalTransactions": 401, "rate": 0.743 }
  ]
}

Admin API

30+ endpoints for program config, tiers, webhooks, API keys, feature flags, branding, and audit. All under /v1/admin. See Authentication for RBAC roles.

Earn Mode in Program Config

The PUT /v1/admin/program endpoint accepts earn mode configuration:

{
  "earnMode": "per-dollar | per-visit",
  "earnRate": {
    "pointsPerDollar": 1,
    "rounding": "floor | ceiling | nearest"
  },
  "visitEarnConfig": {
    "pointsPerVisit": 10,
    "minSpendThreshold": 500,
    "maxVisitsPerDay": 3
  }
}

When earnMode is "per-dollar", the earnRate fields are used. When "per-visit", the visitEarnConfig fields are used. Switching modes does not affect existing points balances.
